## 2. 背景与方案选择

原实现把马赛克区间切成大量 15~90 秒小段，每段新建一个 worker 子进程并重新加载 22B 模型；触发 L2 时协作卡各再加载一次，主进程收尾时又加载一次。

用户指出上游已有任务级加载流程，并批准据此改造。容器内 worker 是官方发布二进制，只能经命令行调用；其 `--segments` 要求输出编码与片源一致，与统一 HEVC 5M 决议冲突，因此不采用。改为调整分段规划：每个渲染块交给一个 worker，worker 内部即走上游任务级加载流程，调度与 worker 调用方式不变。

## 3. 变更内容

1. 重写 `_split_long_render_spans()`：
   - 不超过 `MULTI_GPU_MAX_INNER_GAP`（默认 180 秒）的无码间隙并入同一渲染块；更长的间隙作为 NVENC 快速直通段。
   - 单块工作量超过“总马赛克时长 / GPU 数”的 1.25 倍时二分切分，切点只取无码间隙或安静关键帧；找不到安全切点时不切。
   - 拆出 `_quiet_keyframes()` 与 `_max_inner_gap_seconds()`，删除不再使用的 `MAX_SPLIT_SPAN_SECONDS`。
2. Stage 1 计划缓存键新增 `layout` 与 `max_inner_gap`；缓存计划失效时清空旧的分片与工作目录，避免按序号命名的旧分片被错误复用。
3. 新增三项单元测试：不在连续马赛克中切开、短间隙马赛克约按卡数归并、仅长间隙断块。
4. 同步设计文档第 4.2、4.3、7 节与 `.drone/README.md` 环境变量说明。

## 5. 验收与验证记录

- [x] 本机独立场景验证：谷值切分、无安全切点不切、36 段零散马赛克在 4 卡下归并为 4 块且切点均在间隙、长间隙断块、调大间隙阈值后合并。
- [x] 单元测试：`tests/test_multi_gpu_head_filter.py` 全部 11 项测试在本机与 4× RTX 4090 容器内均通过。
- [x] 真机验证（`8,432.2s` 59.94fps 长视频样本，4× RTX 4090）：
  - **单次 Worker 冷启动与模型重载开销实测**：单次 worker 子进程从启动、运行时校验、CUDA/TRT 初始化（`~11s`）到 3D VAE 编码器、22B DiT（`13.3 GB` 加密权重解密加载 + Triton 算子初始化，`~15s`）及解码器加载，合计固定开销约 **`29s ~ 32s / 次`**。
  - **改造前后渲染块数量与加载次数对比**：
    - **改造前（15~90s 切分）**：64 个原始马赛克区间被切分为 **84 个**渲染分段（含 **20 处**连续马赛克内部切分），全片需启动 84 次 worker、重复加载 22B 模型 **84 次**（累计冷启动开销约 `2,520 GPU 秒` = 4 卡并折合 `~10.5 分钟`）。
    - **改造后（T7 `chunk-v1` 按卡归并，`MULTI_GPU_MAX_INNER_GAP=180s`）**：自动归并为 **6 个**渲染大块（4 个主块含码工作量分别为 `1401.1s`、`1058.3s`、`987.3s`、`644.2s`，辅以 2 个尾块 `119.5s`、`4.8s` 动态补齐最先空闲的两张 GPU，4 卡含码负载均衡在 `763.7s ~ 1401.1s`），22B 模型加载次数从 **84 次降至 6 次**（减少 **`92.9%`**，直接节省约 **9.8 分钟**端到端墙钟时间）。
  - **切口接缝量化对比**：
    - 改造前在连续马赛克中间强行切开的边界（如 `pts=993659` 与 `pts=5095557`），由于相邻两段独立去噪无跨段滑窗重叠，全帧 `L1` 差值较原片跃升 `+3.79 ~ +4.64`（马赛克区域 `p95 L1 = 23.67`）；而在无马赛克安静关键帧切开的边界（如 `pts=7334193`），原片 `source_L1 = 1.30`、修复片 `restored_L1 = 1.26`（`delta = 0.05`，零接缝）。
    - T7 归并后 **100% 切点均落在无码间隙内（连续马赛克内部切点为 0）**，从根源上消除了跨段马赛克切口纹理跳变。

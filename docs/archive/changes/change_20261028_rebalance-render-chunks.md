## 2. 问题

1. **负载不均**：T7 首版目标为每卡一块，切分份数用 `round(工作量 / 目标)`，工作量为目标 1.25~1.5 倍的块被判为 1 份而不切。T5 长片样本四卡负载为 1401 / 1058 / 987 / 644 秒，最重一卡超出理想值约 33%，整片耗时由该卡决定。
2. **粒度过粗**：T5 实测单次 worker 冷启动约 30 秒，约占单块耗时 7%；每卡一块虽然加载最少，但负载不均造成的尾部等待远大于多几次加载的开销。
3. **T7 端到端数据为估算**：T7 记录的“节省约 9.8 分钟”由 78 次加载乘以单次开销再除以卡数得出，并非改造后实际运行的端到端耗时；T7 列出的端到端耗时对比与各卡完成时间差尚无实测记录。

## 3. 变更内容

1. 单块目标工作量改为“总马赛克时长 /（GPU 数 × 3）”与 120 秒中的较大者（`RENDER_CHUNKS_PER_GPU`、`MIN_CHUNK_WORK_SECONDS`）；超过目标 1.25 倍的块按 `ceil(工作量 / 目标)` 切分；单卡时不切分。切点规则不变，仍只落在无码间隙或安静关键帧。
2. Stage 1 计划缓存键 `layout` 升为 `task-chunks-v2`，按首版规则生成的计划自动失效并重新规划。
3. 单元测试 `test_render_chunks_group_short_mosaics_about_one_per_gpu` 改为 `test_render_chunks_group_short_mosaics_into_a_few_per_gpu`，校验最重块不超过平均值的 1.25 倍。
4. 设计文档同步第 4.2、4.3、5、7 节，并按 T5 实测修正各阶段耗时占比。
